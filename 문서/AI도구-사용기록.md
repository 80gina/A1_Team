## 1. 역할 분담 — 무엇을 맡기고 무엇을 직접 했나

| AI가 한 일 | 내가 한 일 |
|---|---|
| 코드 파일 작성과 사전 검증 | **프로그램 실행과 동작 확인** |
| 오류 원인 진단 | **git 명령어 직접 입력** (증빙에 필요) |
| 문서 초안 작성 | **GitHub 저장소 생성** |
| 폴더·커밋 기록 확인 (읽기) | **`.env` 에 실제 키 입력** |
| RSS 구조·robots.txt 사전 조사 | **스크린샷 촬영과 결과 판독** |

**직접 해야 한다고 판단한 것**

| 항목 | 이유 |
|---|---|
| API 키 입력 | 실제 키를 대화창에 붙여넣지 않기 위해 |
| git 명령어 | 커밋 화면 자체가 평가 증빙이다 |
| 프로그램 실행 | 직접 눌러봐야 구술 평가에서 답할 수 있다 |
| 차트 육안 확인 | 한글 깨짐은 파일이 만들어졌다는 것만으로는 알 수 없다 |

**AI가 대신 확인할 수 없었던 것**
AI의 작업 환경에서는 경향신문에 접속이 막혀 있었다.
그래서 **실제 수집이 되는지는 내 화면으로만 확인 가능**했고,
AI는 파싱 로직을 표본 XML로 따로 검증한 뒤 넘겼다.

## 2. 주요 문제 해결 과정 6건

### 사례 1 — 다른 프로젝트의 가상환경이 켜져 있었다

**증상**
```
(.venv) PS C:\Users\yello\코디세이>
```
`python -m pip list` 가 아무것도 출력하지 않았는데,
프롬프트 앞에 `(.venv)` 가 붙어 있었다.

**진단**
VS Code가 **A1-02(travel-recommender)의 가상환경**을 자동으로 켠 상태였다.
그대로 `pip install` 했다면 지난 과제 환경에 이번 패키지가 섞였을 것이다.

**대응**
`deactivate` → 새 폴더 → 새 `venv` 생성 순서로 정리했다.

**배운 것**
프로젝트마다 가상환경을 따로 두는 이유는 용량이 아니라 **재현성**이다.
제출본을 다른 컴퓨터에서 돌릴 때 무엇을 설치해야 하는지가 흐려지면 안 된다.

> 📸 `증빙자료/05_storage.png` 이전 단계

### 사례 2 — 서버가 준 정보를 버리지 않는다 (A1-02의 교훈 적용)

A1-02에서 **403 오류의 본문을 버려 원인을 못 찾았던** 경험이 있었다.
이번에는 처음부터 응답 본문을 오류 메시지에 실었다.

> 📄 `ai_client.py`
> ```python
> if 400 <= res.status_code < 500:
>     raise AIError(f"AI 요청이 거부되었습니다 (HTTP {res.status_code}): {res.text[:300]}")
> ```

시험 삼아 잘못된 키로 호출했을 때 이렇게 나왔다.

```
AI 요청이 거부되었습니다 (HTTP 400): {"error":{"message":"API key not valid"}}
```

"인증 실패"라고만 적었다면 키 문제인지 권한 문제인지 알 수 없었다.
**한 번 겪은 실수를 설계 단계에서 막은 사례다.**

### 사례 3 — AI가 짐작한 모델 이름 (A1-02에서 이어진 문제)

A1-02에서 AI가 `gemini-2.5-flash` 를 제안했다가 **404**가 났던 일이 있었다.
모델 이름은 계정과 시기에 따라 달라지는데 AI가 짐작으로 댄 것이었다.

이번에는 사용할 모델을 내가 지정했고(`3.5 Flash-Lite` / `3.1 Flash-Lite`),
AI는 **짐작 대신 공식 문서를 조회해 정확한 모델 코드**를 확인한 뒤 적용했다.

그리고 구조 자체를 바꿨다.

| 이전 | 이번 |
|---|---|
| 모델 이름 하나를 설정에 둠 | 모델 **목록**을 우선순위로 둠 |
| 404가 나면 사람이 고침 | **404일 때만** 다음 모델로 자동 전환 |

> 📄 `config.json`
> ```json
> "model": "gemini-3.5-flash-lite",
> "fallback_models": ["gemini-3.1-flash-lite"]
> ```

전환 조건을 404로 **좁힌 것**이 중요하다.
400(키 오류)에서 모델을 바꾸면 같은 실패를 두 번 하게 된다.

| 상황 | 전환 | 근거 |
|---|---|---|
| 404 | ○ | 그 계정에서 못 쓰는 모델 — 바꾸면 해결 |
| 400 | ✕ | 키가 틀림 — 모델을 바꿔도 그대로 |
| 429·5xx | ✕ (같은 모델 재시도) | 모델 문제가 아님 |

### 사례 4 — '번개장터' 가 미식축제로 분류되었다

**증상**
```
[ID=3] 미식축제 | 걸린 키워드: 장터
제목: 추석 승차권 암표 뿌리뽑는다
```

중고거래 플랫폼 **번개장터**가 본문에 나왔고, 내 키워드 목록의 `장터` 가 걸렸다.

**중요한 판단 — 재수집하지 않았다**

`raw_news` 158건이 원본 그대로 남아 있었으므로,
**규칙만 고치고 정제만 다시** 돌렸다. 뉴스 사이트에 재요청은 한 번도 하지 않았다.

이를 위해 `clean --rebuild` 옵션을 새로 만들었다.
규칙에 더는 맞지 않는 기사를 clean에서 제거하되,
**살아남은 기사의 AI 요약문은 지우지 않는다** — 다시 API를 부를 필요가 없도록.

**결과**
```
재구축: 규칙에 맞지 않게 된 6건을 clean 에서 제거했습니다.
정제 완료: 3건 저장, 13건 갱신, 135건 제외
```

6건이 빠지고 새 규칙으로 3건이 새로 들어왔다.

**배운 것**
**raw/clean 분리는 이런 순간을 위해 있다.** 교과서적 설명이 아니라
실제로 규칙이 틀렸을 때 비용 없이 되돌릴 수 있느냐의 문제다.

> 📸 `증빙자료/13_rebuild.png`

### 사례 5 — 요약이 요약이 아니었다 (203자 → 148자)

**증상**
```
[7/16] ID=10 요약 완료 (203자 → 148자)
[8/16] ID=11 요약 완료 (203자 → 124자)
```

**진단**
203자는 RSS가 주는 요약문의 길이였다. 크롤링을 5건만 해서
나머지는 본문이 없었고, 결측값 처리 규칙에 따라 **요약문을 본문 대신** 쓴 것이다.
규칙대로 동작했지만 AI에게 줄 재료로는 부실했다.

**대응 — 전부 긁지 않았다**
`--limit 150` 으로 전부 크롤링하면 정치·증시 기사까지 122번 방문하게 된다.
쓰지도 않을 기사다. 그래서 `--target clean` 옵션을 만들어
**정제를 통과한 기사만** 크롤링하도록 했다.

**결과**
```
본문 길이  최소 629자 / 최대 4,473자 / 평균 1,681자
요약 길이  평균 176자
```

**배운 것**
"필요 없는 요청은 아예 보내지 않는다"가 크롤링 예절의 가장 강한 형태다.
지연을 두는 것보다 **요청 수를 줄이는 것**이 근본적이다.

> 📸 `증빙자료/14_resummarize.png`

### 사례 6 — PowerShell 스크립트의 한글 경로가 깨졌다

**증상**
```
'C:\Users\yello\肄붾뵒?몄씠\bapsang-trend' 경로는 존재하지 않으므로 찾을 수 없습니다.
```

`코디세이` 가 `肄붾뵒?몄씠` 로 깨졌다.

**진단**
AI가 만든 `daily.ps1` 이 **BOM 없는 UTF-8** 로 저장되었고,
윈도우 PowerShell 5.1은 BOM이 없으면 **cp949로 간주**해 읽는다.
CSV를 엑셀에서 열 때 한글이 깨지는 것과 같은 원리다.

**모순 지점**
같은 프로젝트의 `export_csv()` 에서는 이미 `utf-8-sig`(BOM 포함)를 쓰고 있었다.
**CSV에는 BOM을 붙였으면서 스크립트에는 안 붙인 것**이 원인이었다.

**해결 — 두 겹으로**

| 조치 | 내용 |
|---|---|
| 1차 | 파일을 UTF-8 **BOM 포함**으로 다시 저장 |
| 2차 | 경로를 아예 적지 않고 `$PSScriptRoot` 사용 |

> 📄 `daily.ps1`
> ```powershell
> $Root = $PSScriptRoot
> $Py   = Join-Path $Root ".venv\Scripts\python.exe"
> ```

`$PSScriptRoot` 는 스크립트가 있는 폴더를 PowerShell이 알려주는 값이라
**경로를 글자로 적지 않으니 깨질 여지가 없다.** 폴더를 옮겨도 동작한다.

**배운 것**
인코딩 규칙은 파일 종류별로 따로 기억할 게 아니라
**"이 파일을 누가 어떤 규칙으로 읽는가"** 를 물어야 한다.

> 📸 `증빙자료/24_schedule.png`

## 3. AI가 만든 것을 그대로 쓰지 않은 지점

### ① 크롤링 본문 추출에 대체 경로를 요구했다

AI의 첫 안은 선택자 하나(`div.art_body`)로 본문을 찾는 것이었다.
사이트 디자인이 바뀌면 프로그램이 통째로 멈춘다.

그래서 2단계 구조를 요구했다.

| 단계 | 방법 | 실제 결과 |
|---|---|---|
| 1 | `config.json` 의 선택자를 순서대로 시도 | 39건 전부 1단계에서 성공 |
| 2 | 실패 시 `<p>` 글자수가 가장 많은 영역을 본문으로 추정 | 사용되지 않음(대비용) |

그리고 **어느 경로로 찾았는지 로그에 남기게** 했다.
1단계가 계속 실패하면 선택자를 고쳐야 한다는 신호가 된다.

### ② AI 응답 형식을 용도별로 다르게 강제했다

AI에게 전부 JSON으로 받자는 안이 있었으나 나눴다.

| 용도 | 형식 | 이유 |
|---|---|---|
| 요약 | 자유 형식 | 사람이 읽을 글. 틀을 씌우면 문장이 딱딱해진다 |
| 인사이트 | JSON 스키마 | 키워드·트렌드를 프로그램이 꺼내 써야 한다 |
| 감성 | JSON + **`enum`** | `긍정`/`중립`/`부정` 셋 중 하나여야 집계가 된다 |

특히 감성은 `enum` 이 없으면 "약간 긍정적입니다" 같은 답이 와서
집계가 깨진다. **집계 가능성이 형식을 결정한다.**

### ③ 스키마를 강제해도 파싱을 방어했다

`responseSchema` 를 걸어도 코드블록이 섞여 오는 경우가 드물게 있다.

> 📄 `ai_client.py`
> ```python
> if cleaned.startswith("```"):
>     cleaned = cleaned.split("```")[1]
> ```

**AI가 만든 규칙을 AI가 못 지킬 수 있다**는 전제로 짠 코드다.

### ④ 차트 색을 용도에 맞게 나눴다

AI의 첫 안은 카테고리마다 다른 색을 칠하는 것이었다. 되돌렸다.

| 차트 | 색 | 이유 |
|---|---|---|
| 카테고리 분포 | **한 가지 색** | 읽는 값은 길이 하나다. 색이 다르면 "색깔별 뜻이 있나" 하고 읽게 된다 |
| 일자별 추이 | **한 가지 색** | 단일 계열 |
| 감성 분포 | **세 색** (파랑/회색/주황) | 좋음↔나쁨 양 끝이 있는 값. 색이 뜻을 나르는 유일한 차트 |

### ⑤ 제안받은 분류 규칙을 실측으로 검증했다

키워드 분류의 정확도를 눈대중하지 않고 결과를 직접 읽었다.
16건 중 2건 오분류(예술 일자리 박람회 → 미식축제, 야구 기사 → 맛집·외식),
**정밀도 약 87.5%**. 이 숫자를 README와 결과보고서에 그대로 적었다.

## 4. AI 도구를 쓰면서 지킨 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | 실제 키를 대화창에 붙여넣지 않는다 | 대화 기록이 유출 경로가 된다 |
| 2 | 검증되지 않은 코드는 받지 않는다 | 오류가 나면 원인이 코드인지 조작인지 구분 못 함 |
| 3 | 오류 화면을 요약하지 않고 그대로 보여준다 | 요약하면 진단 정보가 사라진다 |
| 4 | 제안의 근거를 확인한다 | 모델명 404 사례처럼 짐작인 경우가 있다 |
| 5 | 실행과 확인은 직접 한다 | 구술 평가에서 답할 수 있어야 한다 |
| 6 | **AI가 확인할 수 없는 것을 구분한다** | 실제 수집·차트 한글은 내 화면에서만 확인된다 |

**협업 중 반복된 실수 하나**
AI가 설명용으로 보여준 파이썬 코드와 옵션 설명을,
실행할 명령어와 똑같이 생긴 상자에 넣어 세 번 터미널에 붙여넣었다.
(`ParserError: Missing argument in parameter list` 등)

이후 구분 규칙을 정했다.

| 이렇게 생겼으면 | |
|---|---|
| `python` 또는 `git` 으로 시작 | 실행할 명령어 |
| `def`, `import`, `$` 로 시작 | 코드·스크립트 (입력 금지) |
| `[INFO] ...` | 결과 화면 (입력 금지) |

A1-02에서도 같은 사고가 있었다. **지시가 모호하면 다시 묻는 편이 빠르다.**

## 5. 이번 과제에서 AI 활용의 값진 순간

**하나** — 203자 요약을 보고 "요약이 요약이 아니다"를 알아차린 지점.
프로그램은 오류 없이 정상 동작했다. **품질 지표를 만들지 않았다면 넘어갔을 문제**다.

**둘** — 번개장터 오분류를 발견하고, 고치는 대신 **먼저 raw가 남아 있는지 확인**한 지점.
남아 있었기 때문에 재수집 없이 규칙만 고칠 수 있었다.
설계 결정이 실제로 값을 한 순간이다.
