# 팀 역할 분담 — 팔도 밥상 트렌드 (4인)

> 파이프라인이 **수집 → 정제 → AI → 리포트** 네 단계로 이미 나뉘어 있다.
> 사람을 단계에 맞추면 파일 소유권이 겹치지 않고, 구술 문항도 한 사람에 하나씩 돌아간다.

## 분담 기준 3가지

| 기준 | 내용 |
|---|---|
| **파일 소유권** | 한 사람이 파이썬 파일 하나를 단독 소유. 남의 파일은 고치지 않고 **요청**한다 |
| **평가 문항 1:1** | 과제 목표 5개 = 구술 문항. 넷이 하나씩, 남는 하나는 공동 |
| **막히면 다음으로** | 앞 단계가 늦어도 **가짜 데이터**로 먼저 만들고 나중에 연결 |

## 두 가지 진행 방식

### 안 A — 기존 코드를 뼈대로 (추천)
- 완성본을 `main` 에 두고 각자 담당 모듈을 확장·개선
- 첫날부터 프로그램이 돌아 각자 자기 부분을 실행하며 이해
- 남는 시간을 개선 항목(AI 분류 전환, 소스 추가, 지역 축)에 투입
- **위험** — "한 사람이 만든 걸 나눠 가진 것 아니냐". 담당 영역에 **본인 커밋 3개 + 개선 1건**으로 답한다

### 안 B — 빈 저장소에서 함께
- 새 저장소에서 각자 모듈을 처음부터 작성, 기존 코드는 참고용
- 기여도가 가장 명확하고 모두가 밑바닥부터 배움
- **위험** — 앞 단계가 늦으면 뒷사람이 대기. 인터페이스를 첫날 합의해야 함

### 실전안 — 구조는 A, 내용은 B
폴더 뼈대·`config.py`·`main.py` 골격만 공유 출발점으로 쓰고,
**네 개의 담당 모듈은 각자 빈 파일에서 새로 쓴다.**
기존 구현은 "막혔을 때 열어 보는 답안지"로 둔다.

## 역할 넷

### 1단계 · 수집 담당 — 바깥 세상과 닿는 사람
| | |
|---|---|
| 소유 파일 | `collector.py`, `config.json` 의 `sources`·`crawl` 절 |
| 할 일 | RSS + 크롤링 두 방식 / 타임아웃·재시도, 4xx·5xx 구분 / robots.txt 확인과 지연 |
| 개선 과제 | 소스를 2곳 이상으로 늘리고 사이트별 선택자 분리 |
| **구술 문항** | **"API/RSS 방식과 크롤링 방식의 장단점을 비교해 설명하라"** |
| 근거 숫자 | RSS 요약문 203자 vs 크롤링 본문 평균 1,681자 |
| 산출물 | `fetch` 동작 화면 / 재시도 로그 / 소스 추가 전후 건수 |

### 2단계 · 정제·저장 담당 — 데이터의 문지기
| | |
|---|---|
| 소유 파일 | `cleaner.py`, `storage.py`, `config.json` 의 `categories` 절 |
| 할 일 | 정제 5규칙 / SQLite 스키마와 skip·upsert / 제외 사유 집계 |
| 개선 과제 | 분류 정밀도 측정 후 개선 (현재 87.5%) |
| **구술 문항** | **"raw와 clean을 분리 저장하는 이유와 각 단계의 역할을 설명하라"** |
| 근거 사건 | '번개장터' 오분류를 재수집 0회로 바로잡은 `clean --rebuild` |
| 산출물 | 정제 통과율·제외 사유 화면 / 중복 건너뜀 화면 / 규칙 수정 전후 비교 |

### 3단계 · AI 담당 — 요약·분석·감성
| | |
|---|---|
| 소유 파일 | `ai_client.py`, `config.json` 의 `ai` 절, `.env` 관리 안내 |
| 할 일 | 요약(자유형식)·인사이트(JSON 스키마)·감성(enum) / 키 마스킹 / 404 시 모델 전환 / 실패 시 스킵 |
| 개선 과제 | 키워드 분류를 AI 분류로 전환하고 정밀도 비교 |
| **구술 문항** | **"AI API를 호출해 텍스트를 요약·분석하는 흐름을 설명하라"** |
| 핵심 한 줄 | 무엇을 시키느냐보다 **어떤 형태로 받느냐**가 파이프라인의 성립을 결정한다 |
| 산출물 | 키가 가려진 실행 화면 / 타임아웃 재시도 성공 로그 / 스키마 강제 전후 비교 |

### 4단계 · 리포트·시각화 담당 — 결과를 보여주는 사람
| | |
|---|---|
| 소유 파일 | `reporter.py`, `config.json` 의 `report` 절 |
| 할 일 | matplotlib 차트 2종 + 한글 폰트 / 품질지표·TOP N·인사이트 리포트 / CSV·JSONL·Excel |
| 개선 과제 | 월별·계절별 집계 차트 추가 |
| **구술 문항** | **"수집된 데이터를 집계하고 matplotlib으로 시각화하는 과정을 설명하라"** |
| 준비할 함정 | 기본 폰트에 한글이 없어 `□□□` 로 나오는 문제, `unicode_minus` |
| 산출물 | 한글 정상 차트 PNG / 품질지표 4종 리포트 / 엑셀 열린 화면 |

### 남는 문항 하나는 공동
**"외부 API에서 데이터를 수집하고 오류 상황을 처리하는 방법"** 은 수집·AI 두 사람이 함께 답한다.
4xx 즉시 포기 / 5xx·타임아웃 지수 백오프 / AI 404 모델 전환 — 원칙이 같고 적용 지점만 다르다.

## 공동 영역은 팀장이 갖는다

| 파일 / 일감 | 주인 | 규칙 |
|---|---|---|
| `main.py` | 팀장 | 각자 `cmd_○○()` 함수만 추가. 함수 단위로 나눠 넣어 같은 줄을 안 건드린다 |
| `config.py` | 팀장 | 설정·로깅·키 마스킹. 바꿔야 하면 팀장에게 요청 |
| `config.json` | 절별 분할 | 수집=`sources`, 정제=`categories`, AI=`ai`, 리포트=`report` |
| `README.md` | 팀장 취합 | 각자 자기 절을 써서 전달 |
| 결과보고서 | 전원 | 담당 문항 절은 **본인이 작성**. 부록·타임라인은 팀장 |
| 시연 진행 | 팀장 | 단계별 설명은 담당자가 이어받아 말한다 |

팀장은 코드를 가장 적게 쓰는 대신 **통합과 문서**를 갖는다.
파이썬이 가장 익숙한 사람이 맡으면 병합 충돌을 빨리 푼다.

## 충돌 없이 일하는 규칙

| 규칙 | 내용 |
|---|---|
| **브랜치 이름** | `feature/collect-rss`, `feature/clean-rules`, `feature/ai-summary`, `feature/report-chart` |
| **main 직접 커밋 금지** | 병합은 `--no-ff` 로 — 누가 무엇을 했는지 그래프에 남는다 |
| **하루 주기** | 작업 전 `git pull`, 끝에 `push`. 브랜치를 이틀 이상 묵히지 않는다 |
| **커밋 메시지** | `[담당] 무엇을 왜` — 예: `[수집] RSS 재시도 추가 - 5xx만 3회` |
| **남의 파일** | 직접 고치지 않고 요청한다. 이 한 줄이 충돌 절반을 없앤다 |
| **대기하지 않기** | 앞 단계가 늦으면 가짜 데이터 3건으로 먼저 만든다 |
| **API 키** | 각자 발급, 각자 `.env`. 저장소엔 `.env.example` 만. **대화방에 키를 붙여넣지 않는다** |

## 4주 일정 (1인당 10시간)

| 주차 | 수집 | 정제·저장 | AI | 리포트 | 팀 공통 |
|---|---|---|---|---|---|
| 1주 | RSS 수집·raw 저장 | 스키마·중복 처리 | 키 발급·요약 1건 성공 | 가짜 데이터로 차트 1종 | 인터페이스 합의, 저장소·브랜치 개설 |
| 2주 | 크롤링·오류 처리 | 정제 5규칙·분류 | 인사이트 스키마 | 차트 2종·한글 폰트 | 주 1회 30분 점검 |
| 3주 | **실데이터 연결** | **실데이터 연결** | **실데이터 연결** | **실데이터 연결** | **통합일 — 하루를 통째로 비운다** |
| 4주 | 각자 개선 과제 1건 + 담당 문항 절 작성 + 증빙 스크린샷 | ← | ← | ← | 리허설 2회, 제출 점검 |

> **3주차 통합일을 반드시 잡을 것.** 각자 잘 돌던 코드가 합치면 안 도는 것이 정상이다.
> 이 하루를 일정에 넣지 않으면 4주차가 통합일이 되고 개선도 문서도 사라진다.

## 개인 기여를 남기는 법

| 남길 것 | 왜 | 확인 방법 |
|---|---|---|
| 본인 이름 커밋 **3개 이상** | 기여가 기록으로 남는다 | `git log --author="이름" --oneline` |
| 담당 모듈의 **개선 1건** | "받아쓴 것"과 "만든 것"을 가른다 | 개선 전후 숫자 비교 |
| 담당 문항 절 **직접 작성** | 글이 곧 구술 답변이 된다 | 보고서 절 끝 요약표 |
| 본인 화면 **스크린샷** | 증빙은 본인 화면이어야 한다 | 파일명에 담당 표기 |
| 막혔던 오류 **1건 기록** | 겪고 해결한 것이 가장 강한 답변 | AI 도구 사용기록에 사례로 |

마지막 줄이 특히 중요하다. 잘 돌아간 이야기보다 **막혔다가 푼 이야기**가 구술에서 훨씬 잘 통한다.
